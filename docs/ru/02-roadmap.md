## Этап 0. Комплектация и проверка лотов 📦

- Куплено: модуль **4× V100 SXM2 32GB** с полным NVLink на одной несущей плате (PEX8748, один
  PCIe x16, питание 2×8-pin), **Atermiter X99 Dual X99** (ZX-DU99D4, E-ATX, C612), **2× Xeon E5-2695 v4**.
- Осталось: 8× 32 ГБ DDR4-2400 REG ECC (2Rx4), БП 1600 Вт, 2 кулера LGA2011-3 (Square ILM),
  NVMe, корпус/рама с продувом, вентиляторы static-pressure.
- Проверить комплектность модуля: тесты продавца (70 ток/с одиночно, 841 ток/с в батче),
  целостность мостовой платы NVLink, кабели 2×8-pin достаточной длины.
- Торгуйтесь: продавцы с AliExpress/Taobao/WB идут на скидку 10–20% при торге.

**Критерий приёмки этапа:** всё в наличии, фото плат с обоих сторон сделаны (для споров о возврате).

## Этап 1. Стенд 🔧

- Сборка базы + модулей: прижим SXM2 по регламенту (винты до упора, 16 центральных — 2 оборота
  против часовой).
- Водоблоки: паста крестом, прокладки 5 мм на VRM, опрессовка 24 ч.
- Контур: сначала 360×45 (GPU), затем 240×30 (VRM/доп) — порядок проверен сообществом.
- Питание: ATX + 2× EPS 8-pin от БП; `nvidia-smi -pl 250` после первого старта.

**Критерий:** 4 модуля видны в lspci до установки драйвера; опрессовка без утечек.

## Этап 2. ОС и стек 💿

```bash
# UEFI + Above 4G + ReBAR в BIOS, затем:
sudo apt install nvidia-driver-580-server   # или из tarball — зафиксировать версию
nvcc --version                              # CUDA 12.8 в PATH
python3.12 --version && uv --version
```

**Критерий:** `nvidia-smi -L` показывает 4 GPU.

## Этап 3. Приёмка железа 🩺

```bash
/srv/apps/scripts/llama/verify-gpus.sh
# внутри: nvidia-smi -L (4 GPU), nvidia-smi nvlink -s (линки), topo -m, счётчики ECC
```

- NVLink: `nvidia-smi nvlink -s` — активные линки между всеми парами по топологии платы.
- Стресс 30 мин (`gpu-burn` или прогон большой модели) → ECC-счётчики по-прежнему нули.
- Питание под нагрузкой: замерить ватты на розетке (ожидание 700–800 Вт при лимите 250 Вт/карту).

**Критерий:** 4 GPU, NVLink активен, ECC нули, температуры < 60°C под нагрузкой.

## Этап 4. llama.cpp 🦙

```bash
cmake -B build -DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=70 && cmake --build build -j
# очередь моделей уже качается по расписанию (01:30–19:00)
./build/bin/llama-server -m GLM-4.5-Air-Q5.gguf -ngl all --tensor-split 1,1,1,1 \
  -c 32768 -fa on -ctk q8_0 -ctv q8_0 --jinja
```

- Тюнинг по лестнице: offload → квант → контекст → KV → FA → батчи → спекуляция (см. 03-engines).
- `llama-bench` для повторяемых замеров, PP и TG отдельно.

**Критерий:** GLM-Air Q5 целиком на GPU; замер записан в базу.

## Этап 5. 1Cat-LLM ⚡

```bash
/srv/apps/models/bin/install-1cat-vllm.sh --check   # RAM warn < 96 ГБ — это норма для 27B
/srv/apps/models/bin/install-1cat-vllm.sh 1.5.4 /srv/apps/vllm
```

- Запуск 27B NVFP4 + MTP4: эталон **425 ток/с одиночный (DFlash2), 1139–1264 aggregate @8 параллельных**.
- DFlash2 лучше на коде; MTP4 — на прозе.

**Критерий:** замеры в пределах ±15% эталона (RAM 877 МГц, лимит 300 Вт).

## Этап 9. Творческий слой: TTS и приёмка 🎙

**Статус: заблокирован до сборки стенда** — плата приходит 29.11, RAM не куплена, корпуса нет.
Это «ждать железо», а не «не нужно»: этап остаётся в плане и открывается сразу после Э3.
Качество модели от железа не зависит: ударения, разборчивость и Voice Design проверяются на любой
GPU или даже на CPU (TeraTTSv2 — ONNX), а Volta нужна только для RTF/VRAM и fp16-стабильности.

Писатель и озвучка живут поверх готового стенда ([09](09-books-writing-and-voicing.md)),
но железо уже другое: PyTorch-стек на Volta, а не только GGUF.

- **Сервис, а не скрипт.** `POST /tts {text, voice|ref, instruct, seed}` → wav 48 кГц, плюс
  `/health`, который синтезирует настоящую фразу: пустой `ok` врёт.
- **Каждый движок в своём venv**: у VoxCPM2 и Qwen3-TTS разные версии torch, а сломать рабочий
  TTS в середине рендера тома — самый дорогой вид регрессии.
- **До скачивания весов** — проверка Volta: `python -c "import torch;print(torch.cuda.get_device_capability())"`
  → `(7, 0)` и один короткий синтез. bf16 на Volta нет: везде fp16, следить за NaN (у diffusion-TTS
  это капризнее, чем у LLM).
- **Порядок скачивания:** VoxCPM2 → Qwen3-TTS-1.7B → TeraTTSv2 (страховка по ударениям и CPU) →
  whisper-large-v3 (WER-гейт). F5-RU — отдельно, только некоммерческие пробы.
- **Приёмка:** 3–5 русских фраз, WER через whisper-large-v3 < 5 %, RTF, VRAM, версия torch.
  Если VoxCPM2 на V100 не поедет — это факт, а не повод молчать: альтернативы Qwen3-TTS,
  TeraTTSv2, F5.
- **Рендер тома** — отдельный systemd-юнит (7–12 часов на том), кэш по блокам, сторож проверяет
  синтез, а не `/health`.


### Контракт `/tts` (согласован до кода)

`POST /tts`, тело JSON:

| Поле | Тип | Обязательно | Смысл |
|---|---|---|---|
| `text` | string 1…4000 | да | нормализованный текст: числа прописью, аббревиатуры раскрыты; теги `<ru>` допустимы и снимаются |
| `voice` | string | нет | имя из `cast/voices.json`; взаимоисключимо с `ref` |
| `ref` | base64 wav 6–20 с | нет | клонирование; только легальная запись |
| `instruct` | string ≤200 | нет | описание голоса для Voice Design |
| `seed` | int | нет | тот же seed + voice + text = тот же wav (ключ кэша) |
| `format` | `wav` \| `flac` | нет | по умолчанию wav |

Ответ: `200 audio/wav`, PCM s16le **48 кГц моно**, заголовки `X-Sample-Rate`, `X-Rtf`, `X-Engine`,
`X-Seed`. Ошибки: `400` — пустой/длинный текст или одновременно `voice` и `ref`; `422` — движок
отверг текст (латиница в RU-поле, неподдержанный символ); `503` — модель не загружена;
`504` — синтез дольше таймаута (по умолчанию 120 с).

`GET /health` — синтезирует фразу «Проверка связи.» тем же путём и отдаёт
`{status, engine, sample_rate, rtf, vram_mb, checks:{synth_ok, wav_bytes}}`; пустой `ok` не отдаётся,
`500` при провале синтеза. `GET /voices` — `[{name, engine, f0_hz, gender, notes}]`.

Единицы: аудио — 48 кГц моно s16le; RTF = секунды синтеза / секунды аудио; VRAM — МБ.

**Критерий:** `/tts` отдаёт wav 48 кГц на русской фразе, WER < 5 %, `/health` доказывает синтез,
рендер главы идёт юнитом и переживает рестарт dsh-web.
